# GoDex 超管控制台使用手册

> 状态：Active（超管 / 多租户控制台操作手册）
> 版本：2026-10-26（覆盖多租户商业化：租户管理、加入码、节点可见性与配额、代看授权、转发计量）
> 适用对象：部署并运营一台 GoDex 中心实例的平台操作员（超管），以及需要体验这些功能的测试者
> 相关文档：[multi-tenant-commercialization-design.md](./multi-tenant-commercialization-design.md)（设计依据）、[node-onboarding.md](./node-onboarding.md)（节点接入细节）

本文是**操作手册**：每个功能都说明「在哪、怎么点、应该看到什么」。所有命令都在真实运行的中心实例上实测过（37 项 API 调用，含越权与边界），不是纸面推测。

## 0. 这份手册能让你测什么

| 能力 | 入口（UI） | 一句话 |
|---|---|---|
| 租户管理 | 设置 → **租户管理** | 看所有租户、成员、套餐、共享开关、**节点数上限** |
| 加入码 | 设置 → 租户管理 → 某租户「加入码」 | 让一台节点**不拿中心 web token** 也能加入某租户 |

| 节点可见性 | 节点页 → 点进某节点 | 节点拥有者决定「只我看」还是「同租户可见」 |
| 代看授权 | 设置 → **代看与协议** | 租户**主动、限时**授权平台操作员看自己的节点，全程留痕 |
| 转发计量 | 用量 → **转发计量** | 租户看自己经中心转发的用量 |
| 计量对账 | 设置 → 租户管理 → 转发计量对账 | 超管看逐租户用量 + 总额是否等于各行之和 |

**未实现（不用找）**：紧急模式（双人复核 + 事后通知）。当前只有「显式授权 + 限时 + 审计」这一条通道。

## 1. 十分钟跑起来

### 1.1 启动

```bash
cd <godex 仓库>
go run ./cmd/godex serve --addr 127.0.0.1:8080
```

打开 `http://127.0.0.1:8080`。

> **推荐用独立目录做实验**，避免污染你日常使用的中心：
> ```bash
> GODEX_HOME=/tmp/godex-admin-demo go run ./cmd/godex serve --addr 127.0.0.1:8080
> ```
> `GODEX_HOME` 默认是 `~/.godex`，账号库落在 `<GODEX_HOME>/state/accounts.sqlite`，节点表落在 `<GODEX_HOME>/control/nodes.json`。
> 想从零开始：删掉这两个文件即可（或换一个全新的 `GODEX_HOME`）。**节点表被删不会让已接入的节点复活**，需要重新接入。

### 1.2 拿到超管凭证（web token）

超管身份**就是**那个共享 web token——持有它的人在本实例上被认定为平台管理员（用户名 `local-operator`，`platform_role: admin`）。二选一：

- **环境变量**（最快）：`GODEX_WEB_TOKEN=my-secret go run ./cmd/godex serve --addr 127.0.0.1:8080`
- **配置文件**：`<GODEX_HOME>/godex.yaml` 里
  ```yaml
  web:
    token: my-secret
  ```

> ⚠️ **没有 token 时会怎样**：监听回环地址（`127.0.0.1`）时，**API 完全开放**，任何能访问该端口的人都是超管。监听非回环地址且无 token 时，`serve` 会**拒绝启动**并告诉你原因——这是有意的防呆，不是 bug。
>
> 想让局域网内的人测试，请务必设 token。想故意开一个开放的局域网实例，用 `--allow-anonymous-remote` 显式越过。

### 1.3 登录界面：三种模式怎么选

打开 UI 会看到登录页，`Segmented` 三段：

| 模式 | 用途 | 何时用 |
|---|---|---|
| **共享令牌** | 粘贴 1.2 里的 web token | **你要用超管功能（租户管理/配额/对账），必须用这个** |
| **登录** | 邮箱 + 密码 | 以**某个租户成员**的身份体验租户侧界面 |
| **注册** | 邮箱 + 密码 + 租户名 | 造一个新租户（自服务注册，自动成为该租户 owner） |

> **关键区分**：用「共享令牌」登录 → 你是平台超管，**但你没有租户**，所以租户侧的面（代看授权、自己的转发计量）看不到数据。
> 用「登录/注册」→ 你是租户成员，能看到租户侧的面，但打开租户管理会得到 403。
>
> **这不是权限 bug，是设计。** 想完整体验，请**准备两个浏览器窗口**（或一个正常窗口 + 一个无痕窗口），分别用两种身份登录。

## 2. 角色模型：谁是谁

```
web token 持有者 ──→ local-operator（平台超管）
                      platform_role = admin
                      entitlements = [center_execution, relay_only]
                      tenant_id = 空  ← 注意：没有租户

注册的邮箱账号 ────→ usr_xxx（某个租户的成员）
                      tenant_role = owner | admin | member
                      entitlements = [relay_only]
                      tenant_id = tnt_xxx
```

三条必须记住的规则：

1. **超管 ≠ 能看租户数据**。超管的 `admin` 角色只给「管理平台」的权力（列租户、设配额、签加入码）。要看**租户的节点**，必须有该租户给出的**代看授权**（§3.4）。这是「不做隐蔽访问」的设计后果。
2. **租户永远不能在中心上跑 agent**。`center_execution` 只给超管。租户套餐是 `relay_only`：只能转发/代理到**自己的节点**。
3. **租户管理员管自己的租户，平台不是他的**。租户 owner/admin 打开租户管理会得到 `403 node administration requires the platform "admin" role`。

## 3. 功能操作手册

### 3.1 租户管理面

**在哪**：设置 → **租户管理**（深链 `http://127.0.0.1:8080/settings?tab=admin`）

**你会看到**：

| 列 | 含义 |
|---|---|
| 租户 | 名称 + 租户 id（可复制） |
| 套餐 | 当前 `relay_only` |
| 成员 | 成员数 |
| 节点共享 | **共享开关**：关闭后，同租户成员不能互访对方节点（即使节点已设为「租户共享」） |
| **节点数上限** | 该租户允许拥有的节点数；显示 `已用 / 上限` 或 `不限 (N)` |
| 创建时间 | |
| 操作 | 「成员」列出成员；「加入码」进入签发页 |

下方还有两块：

- **转发计量对账**（§3.5）
- **我在读哪些租户**（§3.4 的操作员侧视图）

**先做这一步**：点一次「注册」造两个租户（如 `a@example.com` / `b@example.com`），再切回共享令牌登录，你就能看到它们。

**为什么共享开关不是「改写节点可见性」**：关掉它**不会**动任何节点的可见性设置，只是让授权层**不再承认** `tenant` 这个可见性。所以开关是可逆的——重新打开，原先的开放范围原样恢复，不需要迁移。你在 UI 上会看到节点可见性那栏**没变**，这是对的。

### 3.2 加入码：让节点不拿中心凭证也能加入

**问题**：旧方式要把中心的**完整 web token** 交给每台要接入的机器——SaaS 场景下等于把平台主钥匙发给所有租户。

**解决**：加入码（`gjt_...`）——**一次性、限定租户、可过期、可吊销**。

**在哪**：设置 → 租户管理 → 某租户行 → 「加入码」

**步骤**：

1. 点「签发加入码」
2. （可选）指定拥有者：下拉里是**该租户的成员**。留空 = 回退到租户 owner
   - 为什么不让你手打 user id：填错会产生一个「谁都访问不到」的节点（默认私有 + 拥有者不是成员），而签发时就会报错拦住你
3. （可选）备注、有效期（默认 24 小时）
4. 点「签发加入码」→ **弹出明文码，只显示这一次**（库里只存哈希）
5. 在目标机器上执行接入

**接入方式二选一**：

*命令行*：

```bash
godex node join 'http://<中心地址>' --id my-laptop --credential <ck_...> --trust trusted --name '车间笔记本'
```

*UI*（节点页 → 接入中心）：填**中心地址** + **中心 web token**。

> 📌 **关于「两个 token」的区别，这是最容易混淆的地方**：
>
> | 值 | 是什么 | 谁该拿到 |
> |---|---|---|
> | **中心 web token** | 平台超管凭证 | **只有你（超管）**。节点页那个「接入中心」表单需要它，因此它是**超管给本机做接入**用的 |
> | **加入码 `gjt_...`** | 一次性租户入网码 | 发给要接入的机器/租户 |
> | **节点凭证 `ck_...`** | 中心签发的**单节点**凭证 | 由接入流程自动写入该节点的 `.env`，你不需要手抄 |
> | **`nk_...`** | 受限的节点代理凭证 | 同上，自动下发 |
>
> 换句话说：**加入码是给「不是超管的人」用的那条路**；节点页表单是「超管在本机操作」的便捷路径。

**你应该看到的结果**：

```json
{
  "node_id": "node-a1",
  "credential": "ck_...",          // 该节点的凭证
  "node_proxy_token": "nk_...",     // 受限代理凭证
  "tenant_id": "tnt_xxx",
  "owner_user_id": "usr_xxx",
  "visibility": "private"
}
```

**属性（都经过测试）**：

- **一次性**：同一个码第二次用 → `401`。且**先消费后注册**，所以并发下也不可能两台设备用同一个码
- **owner 来自码，不来自请求体**：请求体是调用方可控的，自报归属正是要堵的洞
- **不会抢占已有节点**：id 已存在 → `409`，且**该码不会被消费掉**（你可以换个 id 重试）
- **可吊销**：`DELETE /admin/join-tokens/{id}`；已加入的节点不受影响

### 3.3 节点可见性：节点主自己决定暴露范围

**在哪**：节点页（`/nodes`）→ 点进某个节点 → **可见性**卡片

**两档**：

- **私有**（默认）：只有拥有者能访问
- **租户共享**：同租户的所有成员都能访问（前提：共享开关是开启的）

**权限边界（重要）**：

- **拥有者 / 超管**：看到可点的单选
- **同租户的其他成员**：**看不到控件**，只看到一句说明「只有节点拥有者可以修改可见性」

> 这是有意的：**能访问 ≠ 能改暴露范围**。给一个永远报错的开关，会让人以为「我大概有权限」，形成错误的权属认知。所以这里选择不显示。

**默认值**：新节点是**私有**。失败方向选得更安全——忘记声明的节点只会「只有我能用」，而不是「悄悄对整个租户开放」。

**共享开关关闭时**：切到「租户共享」会被拒绝。节点设置不会变，因为授权层根本不认这个可见性。

### 3.4 代看授权：租户主动、限时、留痕地让平台看

**问题**：平台排障时可能需要看租户的节点，但「超管想看就看」不可接受。

**解决**：**由租户主动发出**、有明确时限、每次访问都落审计的授权。

**在哪（租户侧）**：设置 → **代看与协议**（深链 `/settings?tab=access`）

**三步走**：

1. **授权**（`代看授权`卡片）
   - **操作者账号**：必填。为什么不给默认值？留空等于「任意超管随时可看」，那就退化成了隐蔽访问
   - **时长**：默认 2 小时，**上限 24 小时**（UI 的输入框上限由服务端下发的 `max_ttl_hours` 决定，不会让你填一个服务端会拒的值）
   - **事由**：如「排查节点离线」
   - 点「授权」→ 列表出现一行，状态「生效中」
2. **撤回**：随时点「撤回」，**立即失效**，且**不提供无痕续期**——想继续看就得再要一次，租户会再看到一次
3. **看审计**（`代看审计`卡片）：时间、动作、目标、用了哪条授权、放行还是拒绝

**你应该看到的现象（这是本功能最值得测的一点）**：

授权一创建，**租户侧界面顶部立刻出现一条横幅**：

> 有 1 条代看授权生效中
> 操作者：local-operator；最近到期：…。期间平台可查看你的节点，每次查看都会记入审计。
> [管理授权]

横幅 60 秒轮询一次，所以**在另一个标签页新建的授权，当前页面稍后也会出现**。横幅只在**存在生效授权**时渲染——没有授权、或你是操作员（你没有租户），它**不显示**，也不会报错。

**审计是「无论是否有人告知都存在」的**：记录写在授权校验的那一层，不依赖操作员主动上报。

**在哪（操作员侧）**：设置 → 租户管理 → **我在读哪些租户**
只列**发给自己的**授权。这里刻意不做「谁在看谁」的全景地图——那是越权视图。

### 3.5 转发计量与对账

**计量什么**：经中心**转发/代理**到租户自己节点的**请求数与字节数**。**只记元数据，不留存内容**（中心转发租户数据而不留存）。

**三条路径都计**：远程转发、本地直连（中心即自身节点）、**转发失败**。
- 本地直连漏计会让「租户用量」取决于它的节点挂在哪里
- 失败也计，因为「反复打一个离线节点」正是对账要暴露的模式
- **被拒绝的不计**：被中心 403 掉的请求从未到达任何节点，计费等于为被拒的流量收钱

**租户自读**：用量 → **转发计量** tab

> 订阅文字会告诉你：「只统计用量元数据（请求数、字节数），中心不留存你的内容。」
> 窗口可切：最近 1 小时 / 24 小时 / 7 天。

**超管对账**：设置 → 租户管理 → **转发计量对账**卡片

- 逐租户行 + **总计**
- 卡片会给出**结论**，不用你自己算：
  - ✅ 「对账一致：总计 N 次请求，等于各行之和。」
  - ⚠️ 「对账不一致：总计 X，各行之和 Y。差额通常来自平台操作员自身的直连流量。」
- **无租户的那一行会显示出来**（标注为「无租户（平台直连）」）而不是被隐藏——**它正是解释差额的那一行**，藏起来反而让人看不懂

**边界（实测）**：

| 情况 | 行为 |
|---|---|
| 操作员访问「租户自读」接口 | `200`，返回**无归属桶**（他自身的直连流量）。不是 400——操作员没有租户，但「他自己那部分」是有意义的数 |
| 窗口参数非法（如 `hours=abc`） | `400`，**不静默换期**。数字**错**比数字**缺失**更糟 |
| 计量库打不开 | `503`，**不会报 0 用量** |

**注意**：在你没跑过任何转发之前，计量是空的（`requests: 0`、`tenants: []`）。这是正常的——它是**用量**统计，不是配置。

### 3.6 节点数上限（配额强制）

**在哪**：设置 → 租户管理 → 租户表格的 **「节点数上限」**列

**界面**：

- 平时显示一个标签：`2 / 5`（已用 / 上限）或 `不限 (3)`
- 旁边的按钮（显示为「节点数上限」）进入**就地编辑**：填数字 → 保存；或点 ✕ 放弃
- **`0` = 不限**

**语义（每条都有测试钉住）**：

| 行为 | 说明 |
|---|---|
| **0 = 不限，且没有策略行也 = 不限** | 这是最关键的默认值。反过来（缺省 = 0 个节点）会让**升级后所有已有租户**立刻无法再加节点，所以有一条专门的迁移测试守着它 |
| **超限拒绝新节点** | 加入时返回 `409`，消息里说明额度：`tenant node limit reached: tenant tnt_xxx already owns 2 of 2 allowed nodes` |
| **只有「新增占用」才被拒** | 重新保存一个**已经属于本租户**的节点不占额度。否则满额租户的拥有者连改自己节点的可见性都会被拒 |
| **调低上限不驱逐** | 只拒绝**新的加入**，已有节点一个不动。否则一次策略调整会静默让正在跑的机器失联 |
| **未归属节点不算任何人的占用** | 没人认领的机器不会平白吃掉租户额度 |
| **超管修复路径不受限** | `POST /admin/nodes/{id}/claim`（租户管理页的「改归属」）**不受额度限制**——操作员修一个错归属的节点时，不能被他可能正在修的额度挡住 |
| **设额度不会重置共享开关** | 两个端点各只写自己那一列，两个方向都有测试 |

**一个值得亲手验的特性（防幽灵节点）**：超限被拒时，**节点根本不会被注册**。
所以拒绝之后，那个 id 在 `/admin/nodes` 里**查不到**（点「改归属」会得到 `404`）。
早期实现是「先注册、再判额度」，会留下一个**已注册但无归属的幽灵节点**，而 id 被占用后同一台设备**再也重试不了**。现在的实现把「注册 + 归属」合成一次原子写入。

**UI 上超限时的样子**：如果租户已有 6 个节点、你把上限设成 5，标签会变成**橙色**的 `6 / 5`——它是**提示**而非错误，因为「收紧策略后存量超额」是合法状态，怎么处理由你决定。

## 4. 一条完整的手把手验收路径

准备两个浏览器窗口：**A = 共享令牌（超管）**，**B = 注册/登录（租户）**。

### 第 1 步：造租户（窗口 B）

1. 登录页选「**注册**」
2. 邮箱 `a@example.com`、密码 `correct-horse`、租户名 `Acme` → 提交
3. 记下页面显示的租户 id（形如 `tnt_xxxx`）

### 第 2 步：超管看租户（窗口 A）

1. 换成「**共享令牌**」模式，粘贴你的 web token
2. 设置 → **租户管理**
3. ✅ 应看到 `Acme`，成员 1，共享「已开启」，节点数上限「不限 (0)」

### 第 3 步：给租户设配额（窗口 A）

1. 在 `Acme` 行的「节点数上限」列点按钮 → 填 `2` → 保存
2. ✅ 标签变成 `0 / 2`

### 第 4 步：签两个加入码并接入两个节点（窗口 A）

1. `Acme` 行 → 「加入码」→「签发加入码」（备注「车间笔记本」，有效期 24）→ 记下明文码
2. 用该码接入一个节点：

```bash
curl -s -X POST http://127.0.0.1:8080/api/control/join \
  -H 'Content-Type: application/json' \
```

✅ 返回 `201`，含 `credential`（`ck_...`）、`node_proxy_token`（`nk_...`）、`tenant_id`、`owner_user_id`、`visibility: private`

3. 重复签第二个码，接入 `node-a2` → 同样 `201`

1. 签**第三个**加入码
2. 用它接入 `node-a3`：

## 5. curl 速查表

设两个变量：

```bash
BASE=http://127.0.0.1:8080/api
WEB_TOKEN=<你的 web token>          # 超管
SESSION=<租户登录返回的 token>       # 形如 gxs_...
```

### 超管（web token）

```bash
# 看所有租户（含 max_nodes / node_count）
curl -s $BASE/admin/tenants -H "Authorization: Bearer $WEB_TOKEN"

# 平台策略（默认可见性、可用角色）
curl -s $BASE/admin/policy -H "Authorization: Bearer $WEB_TOKEN"

# 某租户的成员
curl -s $BASE/admin/tenants/tnt_xxx/members -H "Authorization: Bearer $WEB_TOKEN"

# 开关节点共享
curl -s -X PUT $BASE/admin/tenants/tnt_xxx/sharing \
  -H "Authorization: Bearer $WEB_TOKEN" -H 'Content-Type: application/json' \
  -d '{"enabled":false}'

# 设节点数上限（0 = 不限）
curl -s -X PUT $BASE/admin/tenants/tnt_xxx/max-nodes \
  -H "Authorization: Bearer $WEB_TOKEN" -H 'Content-Type: application/json' \
  -d '{"max_nodes":5}'

# 全部节点（含归属，跨租户）
curl -s $BASE/admin/nodes -H "Authorization: Bearer $WEB_TOKEN"

# 改归属（不受配额限制）
curl -s -X POST $BASE/admin/nodes/node-a1/claim \
  -H "Authorization: Bearer $WEB_TOKEN" -H 'Content-Type: application/json' \
  -d '{"tenant_id":"tnt_xxx","owner_user_id":"usr_xxx","visibility":"private"}'

# 签加入码（返回明文，只此一次）
curl -s -X POST $BASE/admin/tenants/tnt_xxx/join-tokens \
  -H "Authorization: Bearer $WEB_TOKEN" -H 'Content-Type: application/json' \
  -d '{"label":"车间笔记本","ttl_hours":24}'

# 列 / 吊销加入码
curl -s $BASE/admin/tenants/tnt_xxx/join-tokens -H "Authorization: Bearer $WEB_TOKEN"
curl -s -X DELETE $BASE/admin/join-tokens/jt_xxx -H "Authorization: Bearer $WEB_TOKEN"

# 全平台转发计量
curl -s "$BASE/admin/usage/relay?hours=24" -H "Authorization: Bearer $WEB_TOKEN"

# 我有哪些代看授权（操作员侧）
curl -s $BASE/delegations/mine -H "Authorization: Bearer $WEB_TOKEN"
```

### 租户（session）

```bash
# 注册（创建租户，自己成为 owner）
curl -s -X POST $BASE/auth/register -H 'Content-Type: application/json' \
  -d '{"email":"a@example.com","password":"correct-horse","tenant_name":"Acme"}'

# 登录
curl -s -X POST $BASE/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"a@example.com","password":"correct-horse"}'

# 我是谁
curl -s $BASE/auth/me -H "Authorization: Bearer $SESSION"

# 我的节点
curl -s $BASE/control/nodes -H "Authorization: Bearer $SESSION"

# 改自己节点的可见性
curl -s -X POST $BASE/control/nodes/node-a1/visibility \
  -H "Authorization: Bearer $SESSION" -H 'Content-Type: application/json' \
  -d '{"visibility":"tenant"}'

# 代看：授权 / 列表（含 max_ttl_hours）/ 撤回 / 审计
curl -s -X POST $BASE/tenant/delegations \
  -H "Authorization: Bearer $SESSION" -H 'Content-Type: application/json' \
  -d '{"operator_user_id":"local-operator","scope":"read_nodes","reason":"排查节点离线","ttl_hours":2}'
curl -s $BASE/tenant/delegations -H "Authorization: Bearer $SESSION"
curl -s -X DELETE $BASE/tenant/delegations/dlg_xxx -H "Authorization: Bearer $SESSION"
curl -s $BASE/tenant/delegations/audit -H "Authorization: Bearer $SESSION"

# 协议留痕：读 / 记
curl -s $BASE/tenant/consent -H "Authorization: Bearer $SESSION"
curl -s -X POST $BASE/tenant/consent \
  -H "Authorization: Bearer $SESSION" -H 'Content-Type: application/json' \
  -d '{"accepted":true}'

# 我自己的转发用量
curl -s "$BASE/usage/relay?hours=24" -H "Authorization: Bearer $SESSION"
```

### 节点自助接入（无需任何已有凭证）

```bash
curl -s -X POST http://127.0.0.1:8080/api/control/join \
  -H 'Content-Type: application/json' \
  -d '{"token":"gjt_xxx","node_id":"node-a1","name":"车间笔记本"}'
```

> 注意：`/control/join` **不在** `protected` 后面——加入码**就是**凭证。要求再带 web token 会把「每租户一把主钥匙」的问题原样带回来。

## 6. 常见现象与排查

| 现象 | 原因 / 处理 |
|---|---|
| UI 一片空白或处处 401 | 「共享令牌」模式里 token 没填对。设置 → 客户端 里可以重填 |
| 打开「租户管理」报 403 | 你是**租户身份**。超管功能要切到「共享令牌」 |
| 打开「代看与协议」说没有授权对象 | 你是**超管身份**，没有租户。代看是**租户**授权给操作员，方向不能反 |
| 「转发计量」显示 0 / 空 | 还没发生过转发。它是用量统计，不是配置 |
| 顶栏没有代看横幅 | 当前没有**生效中**的授权（已过期/已撤回/从未创建），或你是操作员。这三种都不该显示 |
| 加入节点返回 409 | 两种可能：① 租户已达上限（消息里会写「already owns N of M」）② 该 node_id 已被占用（**此时代码没被消费**，换个 id 重试即可） |
| 加入节点返回 401 | 加入码无效：不存在 / 已过期 / 已用过 / 已吊销。四种情况**故意用同一条消息**，免得泄露「哪些码存在」 |
| 接入后节点不出现 | 节点需要重启一次 `serve` 才生效；也检查中心地址是否可达 |
| `serve` 拒绝启动，说没有 web token | 你监听的是非回环地址。设 `GODEX_WEB_TOKEN`，或加 `--allow-anonymous-remote` 显式越过 |
| 改了配额但界面没变 | 就地编辑要点**保存**；输入一半的数字不会发出去 |
| 删除节点后又出现了 | 有人重新执行了 `node join` 并重启。那是**重新接入**，属预期 |

## 7. 设计约束速查（测的时候别误判为 bug）

这些是**有意为之**的行为，每一条都有测试守着：

1. **超管看租户数据必须走代看授权**，`admin` 角色本身不构成读权。
2. **租户不能有 `center_execution`**：agent 只在租户自己的节点上跑。
3. **可见性默认私有**：失败方向选更安全的那边。
4. **「能访问」≠「能改可见性」**：所以非拥有者**看不到**那个开关。
5. **共享开关是可逆的**：它不改写节点可见性，只让授权层暂时不认 `tenant`。
6. **它不给你看见「谁在看谁」的全景**：操作员只能列**自己的**授权。
7. **审计不依赖告知**：记录写在授权校验那一层。
8. **代看窗口最长 24 小时，默认 2 小时，不提供无痕续期**。
9. **代看必须指名操作者**：留空等于「任意超管随时可看」。
10. **拒绝的流量不计费**，**失败也计**（那是要暴露的模式）。
11. **非法计量窗口返回 400，不静默换期**。
12. **配额 0 = 不限，且缺策略行也 = 不限**（升级安全）。
13. **调低配额不驱逐已有节点**；**超管修复归属不受配额限制**。
14. **超限拒绝不留幽灵节点**：注册与归属是一次原子写入。
15. **一次性的语义是硬的**：加入码**先消费后注册**，并发下也不可能一码两用。
16. **协议留痕里「没有记录」≠「已同意」**，界面上就是这么写的。
